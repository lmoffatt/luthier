## Bites

### Bite 1. Bool: by label or by position

The specification: labels are binders and not part of a type's identity (04-kernel.md:68-73), so
`< wrong : Unit | right : Unit >` is Bool, and tests/spec/k_bool_is_sum.accept.lut asserts it. The
code: conversion is positional (evaluator.py:1147) while `if`, predicates and laws require the
labels true and false (checker.py:125-131, 1927-1931), and tests/test_checker_rules.py:24-37
asserts that rule, which is written only in docs/plan-2026-10-05.md:384. Result: `b : Bool := v`
with v = wrong prints `wrong : Bool`, takes the true branch, and a law valued in Verdict passes
check and fails test "did not reduce to a Bool"; `Swapped = < false : Unit | true : Unit >` shows a
value printed as true that behaves as false (B39, CORE-2, spec-00-01#12, spec-04#19).
Options: (a) by label, as the plan of 2026-10-05 decided: write it into 04 §2 and 05, make conv
compare labels for labeled sums, flip k_bool_is_sum to a reject file; (b) by position, as 04 says:
accept `if v` on any two-unit sum and drop the label tests. Recommendation: (a); a type whose values
print one thing and act as another is the worse outcome, and (a) is what the checker already does
in three of four places. Cost: one checker change in conv, two test files, a paragraph in 04.

### Bite 2. One program or one file at a time

The specification: the order of acts does not matter, imports included; the checker reads the
whole program and builds one dependency graph, so a type may be declared in one file and defined
by its laws in another (00-fundamental-elements.md:89-92, 05:90-99, 03-libraries.md:23-34,
README.md:64). The code: each import is loaded and checked depth-first in directive order, and
objects are computed per file (cli.py:84-98, checker.py:159-168). Result: `import "b"` then
`import "c"` loads while the swapped order fails; a module sees names it never imported; a theory
declared in one file cannot be defined in the file that imports it (spec-00-01#28, #29, 05#13,
spec-02-03#73, #76). On top: labels of sums named by an alias are not prefixed under `import as`
and collide across modules (spec-02-03#69, #75).
Options: (a) implement the whole-program reading: parse every file first, one graph, then check
objects in dependency order; prefix labels like constructors; (b) amend 00, 03 and 05 to say
loading is per file in import order, and drop the cross-file definition from 03:45 and README:64.
Recommendation: (a); the cross-file definition is a stated feature, and import order as a hidden
dependency is the kind of thing the project exists to remove. Cost: a round of the loader
(cli.py, checker.load, graph.file_objects), every certificate reissued at v0.2 in any case.
Answer:

### Bite 3. Aliases

has no states (04-kernel.md:41; R7, 05:199-201: an alias is never declared, defined or certified).
The code: add_alias elaborates the body once with the alias as current definition and stores a

that is only declared is rejected by R2 (a name used as a type must be defined) although its
expansion is accepted (spec-04#06, 05#35, 05#36, B05).
Options: (a) expand aliases at their uses, as 04 and R7 say (a macro, re-elaborated per use);
(b) keep aliases as checked definitions and rewrite 04:41 and R7 to say so, including that an
alias can owe and be certified. Recommendation: (a); it removes a false failure and a state the
specification says doesn't exist. Cost: a checker change at add_alias and resolve, possibly slower
checking of files that use an alias many times; tests r7_* keep passing.

### Bite 4. Operators and R8

makes `3 < 4` evaluate to 12; and contains_function answers False for a type variable and for U

`Same (Int -> Int) idf idf` is the stuck term `idf == idf : Bool`, printed as a value (B51, B53,
E08, 05#39, spec-02-03#24, GRAM-9).
Options: (a) limit `operator` to + - * / and mod, check R8 before user operators, and reject == at
a type variable and at U, which forces the eq parameter R8 asks for; (b) allow any operator as 04
says and amend 02:65 and R8. Recommendation: (a); the base library registers only + - * (grep
^operator in lib/), and a monkeypatch that flags == at a type variable fires on nothing in lib/.
Cost: small; 04:49 corrected to match 02:65.

### Bite 5. Parentheses and associativity in types

through an alias; arithmetic stays left-associative, as it should (GRAM-5, spec-04#20).
Options: (a) right association for `*` and `+` on types, as 04 says, correct 02:62, and keep
parentheses in the tree so a left-nested type can be written; (b) left association everywhere.
Recommendation: (a); `(a, b, c)` as `(a, (b, c))` is already what 04:76 fixes for values. Cost: a
paren node in the parser or no flattening across explicit parentheses; one line of 02.
