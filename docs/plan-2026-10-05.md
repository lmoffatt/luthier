# Repair plan, 2026-10-05

What the review of 2026-10-05 found in the Luthier interpreter and in its use in sonolocalización,
and how each problem gets fixed. Each item gives the problem, why it matters, the fix, and its
caveats. Tags say where the fix lives: [int] the interpreter, [spec] a line in the specification
(`docs/semantica`), [proj] the sonolocalización project (`prototipo-cero/luthier`, `prototipo-cero/src`).

The fixes come in layers, and the bridge with Python comes first: while an extern can return
anything, no certificate says anything. Phases are in the order they should be done; within a
phase, items are ordered by harm.

Status: phases 1 to 4 done (2026-10-05), see the sections "as done" at the end. Certificates regenerated after phase 4.

## Phase 1. The bridge with Python (2 to 3 days)

**1.1 `from_python` accepts any `int`, `float` or `str` for any type, and arithmetic follows the
Python type.** [int]
The only problem on this list that can give a wrong number without warning (`3 / 2 = 1` as a
`Float64`). Everything else (laws, certificates) assumes a value of type `Float64` is a double.
Fix: `from_python` uses the declared type as a contract. `Int` requires an `int` (not a `bool`) or
a numpy integer, with the 64-bit range when it crosses into numpy (`06 §6`); `Float64` requires a
`float` or a numpy floating value, promotes an `int` explicitly (the one safe promotion) and rejects
a `str`; `String` requires a `str`; `Fin n -> Int` requires an integer dtype and `Fin n -> Float64`
a float dtype; NaN and infinities are errors everywhere, inside lists too. `--set` parses by the
declared type of the hole. With values normalized at the border, arithmetic by Python type is
right without touching the evaluator.
Caveat: externs that return `np.float64` where `Int` was declared start to fail, which is the point,
but each one has to be reviewed.

**1.2 A refinement in the codomain of an extern raises no law.** [int] [spec 05 R5]
`neg : Float64 -> NonNegative := extern` is a promise nobody tests. `abs` in `real.lut` gets around
it by writing its type as a subtype of the function type, which is a trick, not a rule.
Fix: for an extern whose type has a refinement anywhere along its arrows or components, the checker
raises the obligation quantified over the domains, as if the author had written the law-lambda.
Optionally, `run --checked` tests the refinement on every value that crosses.
Caveat: domains with no generator stay pending. `--checked` over large arrays is costly; it is for
debugging, not for the run.

**1.3 Registered Python generators skip the predicate of the subtype.** [int]
`gen ValidDistanceGraph := gen_good_graph` is believed by name; if the generator is wrong, the laws
pass over graphs that are not valid. Case 9, open in `05 §10`.
Fix: after a registered generator, test the type's predicate, reject what fails, and record in the
certificate how many values each generator had rejected. A generator that is mostly rejected is an
error.
Caveat: evaluating an interpreted predicate on large values costs. If it is prohibitive, allow
`gen T trusted := ...`, recorded in the certificate as declared trust, never silent.

**1.4 Tables `Fin n -> Int` are sampled as `float64`.** [int]
Fix: `int64` when the codomain reduces to `Int` or a `Fin`, plus the range check. Depends on 1.1.

**1.5 Aliases carry a generator, against R7.** [int] [spec]
`BrokenGraph = DistanceGraph` has no identity under R7, yet `gen BrokenGraph` hangs a distribution
on it: the type of a law's parameter carries something the type system says does not exist.
Fix: a generator belongs to a type, and an alias is transparent, so `gen` on an alias registers a
generator for what the alias stands for, and two generators for one type are an error.
`BrokenGraph : U := { g : DistanceGraph | not (ValidGraph g) }`, `CompleteGraph` with its predicate
(every pair measured), and `GoodGraph` gives way to `ValidDistanceGraph`. With 1.3 the generator
is checked against the predicate, and the distribution sits where it belongs: a sample of a type
with a law.
Caveat: the predicate must be decidable in Luthier; for `CompleteGraph` it is a `forallPairs`.

## Phase 2. Certificates that can be trusted (3 to 4 days)

**2.1 The cone hash ignores the Python behind externs, the generators, `n`, and the interpreter
version.** [int] [spec 05 §7]
Editing `lm.py` invalidates nothing. Most of what runs is externs, so this is the most dangerous
gap for the project.
Fix: the hash includes, for each extern of the cone, the hash of the source file of its Python
module (`inspect.getsourcefile`), and for modules with no source (numpy, builtins) the package name
and version; also the Luthier version, the generators used, and the mode and `n` of the directive.
Caveat: hashing the whole file invalidates certificates on edits to unrelated functions of the same
module; conservative and acceptable. Hashing only the function with `getsource` is finer and fragile
(decorators, closures).

**2.2 Certificates that depend on holes never match.** [int] [spec 05 §7]
`accept_certificate` runs when each file loads, before the parent fills the holes; the stored hash
was computed after. 37 entries show as stale under `algebra_python`, and 56 of 72 names with laws
in the cone of `experiment_zero` are pending, though all were certified the same day.
Fix: compare hashes at the end of `load`, with the whole program loaded and the holes filled, and
accept what follows from `03 §1`: a library with holes is a structure with parameters, certified by
instantiation. A certificate keeps a list of entries per name, each with its hash (one per filling).
Caveat: a library imported by two projects with different fillings gets two entries.

**2.3 "Exhaustive" over `Int` means [-16, 16].** [int] [spec 05 §7]
Fix: the grade `exhaustive` only on a domain that is finite after reduction (`Fin`, `Bool`, sums and
products of finite types, finite `data`); over `Int` or `Float64` the mode is `bounded` with its box.

**2.4 `provisional` externs are certified without a mark.** [int]
Fix: the entry carries `provisional: [names]`, never `certified`, and `check -v` lists it. Settle
the point open in `05 §10`: a file that imports a provisional name inherits the mark in everything
that depends on it.

**2.5 Pending is recorded as failed, and some failures are false.** [int]
`meanDist (t : HasFree)` fails on a `t` of length 0, which is not a `HasFree`; `pairDistances` fails
with `j.n /= i.n`, which violates `Pairs p i`. "No generator for U" and "out of fuel" show as
`passed: false`, like a real counterexample.
Fix: three outcomes in the certificate, `passed`, `failed` (with its counterexample) and `not run`
(with its reason). An obligation raised by passing a parameter `x : S` where `S` is required is
discharged by the checker, not sampled; when it is sampled, it is quantified over the declared type
of the parameter with its dependencies.
Caveat: static discharge needs a comparison of predicates; syntactic equality after alpha
normalization covers the project's cases.

**2.6 Obsolete entries accumulate.** [int]
Fix: `luthier test` prunes names that no longer exist and moves entries whose hash does not match
to a `stale` section; a `luthier certify [files]` command runs every directive of a set of files,
prunes and summarizes.

**2.7 `run` records nothing about the state of its cone.** [int] [spec 05 §7 asks for it]
Fix: `.run.json` carries, per name of the cone, its state (certified, stale, pending, provisional,
not run), the Luthier commit and the hashes of the Python modules; `run` prints a warning with the
counts, and `run --require-certified` fails unless everything is certified.

**2.8 Import accepts an entry with a matching hash whatever its `n`.** [int]
Fix: with 2.1 `n` is in the hash; also, accept only when `cases >= n` of the current directive.

**2.9 Grades promised by `05` that do not exist; `test n` does not run the object.** [int]
Fix: `assumed` for axioms; `test n` expands to the members of the strongly connected component of
`n`; the grade of a chain is the minimum over its cone. `witnessed` waits for existential laws.

## Phase 3. Semantics of the checker (2 days)

**3.1 `Bool` by position.** [int] [spec 04]
Any sum of two `Unit`s is a `Bool` and alternative 0 is `true`; a verdict `wrong` passes.
Fix: `Bool` is the type of `core.lut` and nothing else, or, if the structural reading stays, it
requires the labels `true` and `false`, never the position.

**3.2 `==` on `Real`, on `data` holding functions, and the cut at depth 20.** [int]
Fix: `Real` has no `==`; `contains_function` walks the constructor types of a `data`, memoized by
name instead of cut at 20.

**3.3 `float64Field : OrderedField Float64` holds only inside [-16, 16], and its type says
everywhere.** [spec 06] [int]
Associativity fails at (1e8, -1e8, 3e-9).
Short term: the carrier says the box, `{ x : Float64 | abs x <= lawMagnitude }`. Long term, `06 §8`:
the rounding law, testable exactly with `Rational` over Python's `Fraction`, from which the
tolerance of a sum of n terms follows instead of `roundingSlack`.
Caveat: the long-term fix needs `Rational` as a primitive, about a week.

**3.4 `Real` is nominal; `toFloat64` is `Int -> Float64`, and the checker's hint suggests calling
it on a `Real`.** [spec 06] [int]
Fix: `toFloat64 : Real -> Float64` as `06 §4` says, `intToFloat64` for integers, fix the hint, and
`check -v` says that no law over `Real` is tested.

**3.5 R2 approximate; R3 when the law cannot be unfolded.** [int]
Fix: R2 by type position as `05 §0` defines it, walking `Inj.type`; R3 reports "undecidable" instead
of counting every label as touched.

**3.6 The reports of `05 §6` do not exist.** [int] Low priority.

## Phase 4. Speed (2 to 3 days)

**4.1 `check` of anything importing `array` takes 17 to 19 s.** [int]
Every nested `+` or `*` infers its leftmost operand again, and several paths check twice.
Fix: memoize inference in `_type_operand`; replace "check silently, then for real" with deferred
errors; a disk cache of each file's elaboration keyed by the file hash and the Luthier version.
Caveat: the cache misses whenever the interpreter changes, daily for now; profile first.

**4.2 `run experiment_zero` takes 3 minutes.** [proj] [int]
The likelihood runs interpreted; the maximizer and the linear algebra are already Python.
Fix: generalize the Python side to take the design of the graph (5.3) and run the fast likelihood,
certified against the native one, which becomes an oracle.
Caveat: three minutes do not matter for the tape; they matter for the acoustics.

**4.3 Two evaluators, with a silent fallback.** [int]
Fix: count fallbacks in the report of `test`; differential tests between the machine and the
substitution evaluator over `tests/spec`; one evaluator in the medium term.

## Phase 1, as done (2026-10-05)

**1.1** `from_python` (`evaluator.py`) reads a value by its declared type: `scalar_kind` names the
primitive a type refines, `_scalar_from_python` checks and promotes, `_array_for` gives an array the
dtype and the number of dimensions its type says, `_check_array_finite` no longer swallows
exceptions, and a number or a tuple where a known structure is expected is an error. `run --set`
reads the value by the hole's type (`typed_setting` in `cli.py`).

**1.2** `Checker.extern_obligations` walks the type of every extern, declared or inline, and raises
an obligation for each refinement it reaches through arrows, records, pairs and array entries. It
does not enter sums or data types, so the `Table` of a `Maybe Table` is still unchecked (07 §9).
In the libraries it added no obligation, because the leaves carry no refinement in their codomains.

**1.3** Every value of a registered generator, in Python or in Luthier, is checked against the
predicates of its type (`Generators.from_registered`). Departure from the plan: a value outside is
an error, not a value drawn again and counted. A negative control drawn from
`{ g | not (ValidGraph g) }` restates its domain, so what it certifies is that the generator and
the type agree, and a silent redraw would hide exactly that disagreement. The certificate records,
per registered generator, how many values each test drew (`registered_values`). Probing the laws of
a type on a value treats an empty domain (`Fin 0`) as vacuous (`EmptyDomain`).

**1.4** The table of a function to `Int` is an `int64` array.

**1.5** `gen` on an alias is keyed by the type the alias stands for (`generator_key`), and two
generators for one type are an error. What it took:
- `table.lut`: `TableText` is gone (`Canonical` takes a `Perturbed` and reads its text), and
  `BrokenText` is the record `{ text, defect }`; `gen_broken` returns the text with the name of
  its defect. As aliases of `String`, either generator would have been the generator of every string.
- `distance_graph_python.lut`: `BrokenGraph` and `CompleteGraph` are types with their laws
  (`not (ValidGraph g)`; every pair measured and the prior means not on one plane), and `GoodGraph`
  gives way to `ValidDistanceGraph`.
- `distances.lut`: another session had made `ThetaPos` and `ThetaFull` aliases of `Vec Float64`
  (reason in 07 §9), which made their two generators generators of every vector. The laws now
  quantify over `FreeCoords = VecOf freeDim` and `FullCoords = VecOf (freeDim + 1)`, which carry
  the generators; `Likelihood ThetaPos` and the rest are unchanged.
- What this exposed: `fullPair : DensityPair ThetaFull`, `profilePair` and `fullKernel` claimed
  the fast likelihood is a density pair on every `Vec Float64`, which is false; it is one on the
  vectors of dimension 16 (15 for the profile). The generator found by the alias's name had been
  supplying the dimension. They are now stated over `FullCoords` and `FreeCoords`, with a
  likelihood whose shift moves only along directions of the parameter's dimension (`fullOn`,
  `profileOn` in `distances_python.lut`). The general fix is a `Likelihood` that carries the
  dimension of its tangent space (07 §9).
Caveat: an instance generator (`gen FullCoords`) draws every `VecOf 16` in a program that imports
it, including laws of other libraries checked there with `--deep`. Those laws hold for every
`VecOf 16`, so this changes the sample, not the claim.

Not done in phase 1: `run --checked` (the refinements of the values that cross, at run time), and
`gen T trusted`, which was not needed.

Tests: `tests/test_bridge.py` (19 cases, one per behaviour above, with `tests/bridge_externs.py`).

## Added 2026-10-05, after phase 1

**Rule, from Luciano:** a project has no Python of its own except the functions its `.lut` files
call through `extern` (and `gen`). The conditions are stated in Luthier; Python implements them,
certified against them. `prepare_experiment_zero.py` is excluded on purpose: it is the logic of one
experiment.

**5.10 `validate_distance_graph.py` is a script.** [proj] The invariants are already in
`distance_graph.lut`; the script walks them in Python and reports the first failure. Fix: the first
violation of a graph, defined natively in `distance_graph.lut` in the order of `ValidGraph`, with its
law (it reports nothing exactly when the graph is valid); a Python `first_violation` bound in
`distance_graph_python.lut` and certified by that law and against the native definition; the entry
a `main` in `validate_graph.lut`. The script goes.

**Patches of phase 1, to be removed:**
- `fullOn` and `profileOn` (`distances_python.lut`) give a shift along a direction of another
  dimension the meaning "stay", so the density pairs type over `FullCoords`. The fix is a
  `Likelihood` that carries the dimension of its tangent space (07 §9), in `probability.lut`.
- `BrokenText = { text, defect }` (`table.lut`) avoids the alias rule by structure; the honest type is
  a predicate, which needs the grammar of the format written natively.
- An instance generator (`gen FullCoords`) replaces the family generator of `VecOf` for one size.
The heuristics of the interpreter that make up for weak generators (intervals of `Int` enumerated
exactly, small sizes skipped when rejection cannot reach the type, predicates decided on the machine
with the substitution evaluator as fallback) wait for generators built from a type's constructors
(`05 §10`).

## Phase 2, as done (2026-10-05)

**2.1 and 2.2.** `certify.fingerprint` is the code of the cone, the Python behind every extern it
calls (`module_fingerprint`: the source files of the module's directory, or the installed package and
its version), and the interpreter (`interpreter_fingerprint`: the package's sources and core.lut);
the hash is of all three. An entry also records the generators it drew from with their
fingerprints, and its `n` and mode. `Loader.accept_certificates` compares once everything is loaded,
and records why an entry is not trusted (`stale_why`), which `check -v` prints. A certificate keeps
up to four entries per name, one per filling; `luthier test f --imports` runs the imported
obligations with no entry for `f`'s program and writes them to their files, under a lock.

**2.3.** "bounded" for an enumeration that took `Int` in a box; a refinement of `Int` bounded on both
sides by closed integers is enumerated over its interval and stays "exhaustive".

**2.4.** A test whose cone has a provisional extern records it in the entry, and is never certified.

**2.5.** Three outcomes, passed, failed and not run, for each law and each definition. The false
failures of `positions` came from certificates of an older `positions.lut`, not from the
quantification: run again, `point`, `pairDistances` and `distanceJacobian` pass. What did need a
change: a type the rejection sampler cannot reach at a small size (a matrix of 3 rows at size 1)
skips that case instead of aborting the law, and the law is not run only if the type is out of reach
at the full size too. The static discharge of obligations was not needed for these cases and is not
done.

**2.6.** Names that no longer exist are pruned when a certificate is written, and entries written
before fingerprints are dropped. `luthier certify f1 f2 ... [--imports] [--jobs n]` tests several
files at once, each in its own process.

**2.7.** `luthier run` prints the states of the names with laws in its entry's cone, records them in
`.run.json` with the fingerprint and the revision of the interpreter, and `--require-certified`
refuses to run unless all are certified.

**2.8.** An entry with fewer cases than its directive asks, or not exhaustive when the directive is,
is not trusted.

**2.9.** `test n` runs the obligations of every member of `n`'s object (the checker keeps
`object_of`). Axioms are listed as assumed by `check -v` and in the cone of a run; the grade of a
chain is read off the cone states of a run, not computed as a minimum.

Also: checking a registered generator's value against a quantified law of its type types the law
from its declared type (`applied_type`) or from the annotations of an elaborated lambda, instead of
calling the checker per value; `table_python` went from 45 s back to about 5.

Tests: `tests/test_certificates.py` (8 cases).

## Phase 3, as done (2026-10-05)

**3.1.** `Bool` is told by its labels `true` and `false`, in the checker (`is_bool`), the evaluator
(`as_bool`) and the bridge. A sum of two other units is not a Bool, so a law valued in
`< wrong | right >` is rejected as a predicate. Found on the way: in a pattern, a name that is
neither a label of the matched type nor a constructor is a variable, so the `true` of an `if` on a
`Verdict` bound anything and the `if` always took its first branch, with no error. `true` and
`false` in a pattern now require a Bool.

**3.2.** No `==` on `Real`, whose equality is the axiom's. A data type is looked into through the
types of its constructors, instantiated, with a set of the types already being looked into in place
of the cut at depth 20, so a recursive type that holds a function has no `==` and one of numbers has.

**3.3, not done as planned.** Narrowing the carrier of `float64Field` to the box
`{ x : Float64 | abs x <= lawMagnitude }` does not work: the box is not closed under the operations
(16 + 16 is 32), and `sumTo`, `pow` and the vector spaces of `algebra_python` are built on this
instance, so every sum would owe a false obligation. The doubles are not a field under any fixed
relative tolerance (cancellation), and the object that represents them is the field with the rounding
law of `06 §8`, the long version. The comment of `float64Field` now says where its laws are false
and why; its own phase is the rounding law, with `Rational`.

**3.4.** The specification follows the code: `toFloat64 : Int -> Float64`, the nearest double to an
integer (37 uses), and the rounding of a `Real` waits for a `Real` that computes (`06 §4`). The
checker's hint no longer points to a conversion that does not exist, and `check -v` says that the
laws of an axiom are never tested.

**3.5.** R2 walks the type of an injection, the result type that elaboration keeps on a lambda, and
the type of an extern written inside a body. R3 reports a law whose labels it cannot read, instead
of counting them all as touched (`LUTHIER_R3_REPORT=1` lists such laws without failing; no file of
the libraries or the project has one).

**3.6** is left out, as planned.

Tests: `tests/test_checker_rules.py` (8 cases).

## Phase 4, as done (2026-10-05)

**4.1.** Three causes, three fixes, measured on loading `array.lut` (14.9 s before) and
`array_python.lut` (17 to 19 s):
- `_type_operand` inferred the leftmost operand of a chain `a + b + c` again at every `+`, quadratic
  in its length. It now decides by the operand's form where it can (a literal, a local of a type
  that is not `U`, a function whose result is not a type), and memoizes the inference otherwise.
- `resolve_operator` inferred the right-hand side twice, silently and then for real, which doubled
  at every level of a nested expression. It infers it once, records its obligations, and takes them
  back if no meaning of the operator takes it. Candidates whose domain cannot meet the operand's
  type (a primitive against a record) are discarded before any conversion test.
- The certificates of phase 2 rendered and walked the cone of every name at load; the references,
  the rendered line and the externs of each definition are now computed once (`_certify_cache`).
Result: `array.lut` 4.5 s, `array_python.lut` 3.8 s, `experiment_zero.lut` 4.6 s, the interpreter's
suite from about 24 s to 6. The disk cache of the elaboration was not built: at these times it does
not pay for itself.

**4.2.** The profile of `experiment_zero` (86 steps of Levenberg-Marquardt) put almost all of its
time in turning the Jacobian into an array, entry by entry: each of its 22 x 30 entries computed the
distance of its row again. `distanceJacobian` in `positions.lut` now binds a row's nodes and distance
outside the function of its column, the same operations on the same values: the run goes from 146 s
