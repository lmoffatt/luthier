## 2. Closest candidates

**Ciao assertions.** This is the closest match for F2 and F3 together. Properties are ordinary predicates. Each assertion carries a status: `check` (to be checked, the default), `trust` (taken as given), `true` (output of analysis), `checked` (proved) or `false` (refuted). The paper says assertions can also describe modules "not yet written or are written in other languages", which is close to F4 and F6. Preconditions are used as value generators, including random ones, and "static checking of assertions can safely avoid (possibly parts of) unit test execution". It differs from Luthier in three ways: there are no graded statistical evidence levels, no content-hash keys, and the "chain graded by its weakest link" isn't spelled out. **Mechanism to take:** leaving an assertion in `check` status is an acceptable outcome. Only the part analysis couldn't prove becomes run-time checks and tests, so proof and testing are one pipeline over the same assertion (https://arxiv.org/abs/1102.5497, sec. 4). The 2025 Checkification paper applies the same machinery to test the analyzer itself, which is a precedent for F11's "the host is certified".

**Sage.** This is the strongest F1/F12 match found. It has refinement types over arbitrary executable predicates, `* : *` (types are first-class terms) and dependent function types `x:S → T`. Subtyping that can't be decided becomes a run-time cast. When a cast fails, the refuted judgment goes into a database, and later compilations reject any program that relies on it; proven judgments are cached in the same database. It differs from Luthier in having no generators, no graded evidence, and run-time checks only on real executions (the paper lists randomized testing as future work). **Mechanism to take:** before looking up or storing a judgment, Sage puts it in canonical form. It drops environment bindings that aren't referenced and replaces variable names with de Bruijn indices, so equivalent judgments hit the same entry (sage-tr.pdf, rule [As-Db]). Luthier's certificate hash should be computed on a canonical form like this, otherwise renaming a variable invalidates the evidence.

**Clojure spec (with Malli).** Specs are predicates, generators come from the specs, `fdef :fn` relates arguments to result, and `stest/check` generates the test of a function from its spec. That matches "defining a function defines its test" (F2). It's a library, nothing is persisted (no F3), and there are no laws across several operations. **Mechanism to take:** `instrument` with `:stub` replaces a function by a stub that checks `:args` and generates a return value from `:ret`. A Luthier hole (F4) could get a runnable stand-in drawn from its type, so the code that depends on it can be exercised before the hole is filled (clojure.spec.test.alpha API).

**Unison.** This is the only system found where test results are keyed by content hash: a result is reused until something in the test's dependency graph gets a new hash. Determinism is enforced by forbidding IO in cached tests. Results are pass/fail with no grade, and seeds and number of cases aren't recorded in the documentation I read. **Mechanism to take:** only cache certificates of computations that are pure or explicitly seeded, and enforce that in the language (abilities) instead of trusting it. The same hash-keyed cache drives incremental evaluation of datasets, which is relevant to F10.

**Pyret.** Pyret is aimed at education. It has the closest match for F7 and F13. Numbers are either Exactnums (exact rationals) or Roughnums. Any operation with a Roughnum argument gives a Roughnum result ("contagion"), and comparing Roughnums for equality throws an error. Tests attach to definitions with `where:`, and `is%(pred)` takes the equality relation as an argument (`is-roughly` is `is%(within(0.000001))`). It has no generated cases and no evidence records. **Mechanism to take:** make exact equality on the realization type an error, so a law over reals checked on doubles has to name its comparison and tolerance (pyret.org numbers and testing docs).

## 3. Features with nothing found in this cluster

- F5 beyond equivalence: measuring cost and choosing the fastest implementation per case, with the choice recorded. Only equivalence checking exists (CrossHair `diffbehavior`, Hypothesis `ghostwriter.equivalent`).
- F3 in full: no grade ladder (point / sampled / bounded / exhaustive / proved / assumed), no weakest-link grading of chains. Ciao statuses and the Sage and GNATprove caches are the nearest.
- F8: Bayesian reading of evidence with the prior as a parameter. Statistical levels exist only for coverage (QuickCheck `checkCoverage`), never for the law itself.
- F10: full provenance (input hashes, script version, every parameter, seed) attached to results.
- F11: interpreter stated in the language and the host certified against it (Checkification is the only partial match).
- F12: universes and initial-algebra `data` in a contract system (only Sage has `* : *`).
- F14: nothing in the cluster.
- F15: no laws valued in a discrepancy or cost. Ciao has cost assertions, but those are resource bounds; Hypothesis `target()` is only a search heuristic.

## 4. Outside the cluster

- **L4 (Legalese).** A DSL for law. Its design principles include "Code should be understandable by legal professionals" so that "Domain experts should validate the encoding" (verified: https://legalese.com/l4/concepts/language-design/principles.md). A search snippet from https://l4.legalese.com/reference/introduction/principles says L4 is "intended to be largely written by machine, but reviewed and revised by humans"; that page failed to load (TLS error), so the sentence is UNVERIFIED. This is the closest F14 precedent I found: a non-programmer expert reads, a machine writes.
- **Signal Temporal Logic robustness semantics** (cyber-physical systems). A specification evaluates to a real number, where the sign says satisfied or violated and the magnitude says by how much, and falsification tools (S-TaLiRo, Breach) minimize it as an objective. That's F15 in practice: laws valued in ℝ (the reals) and turned into a loss. Source: https://arxiv.org/pdf/2005.02126 (search-level only, not read in full: UNVERIFIED in detail).
