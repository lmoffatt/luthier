## 2. Closest candidates

**Caesar / HeyVL.** This one is closest to F15 with Bool as the logical limit. HeyLo formulas map states to the extended non-negative reals. The docs say `assert e` gives `min(e, f)`, and that "?(b) is ∞ when b holds and 0 otherwise", so a Boolean law is literally a cost law with two values. HeyVL encodes proof rules as programs. It differs from Luthier in being a deductive verifier for expected values with no testing, generators or priors, and in using the opposite orientation (∞ = true, larger is better). Lawvere's convention is 0 = true. Luthier has to pick one; the two are order-dual, so either works, but it should be stated once. One mechanism worth taking is slicing for correctness (https://www.caesarverifier.org/docs/caesar/slicing, https://arxiv.org/abs/2512.20214): it removes as many statements as possible while verification still succeeds, and reports "assumption is not necessary". That is a concrete way to compute which assumptions a certificate actually rests on (F3: every chain ends in assumptions). The docs describe no stored certificate file.

**Vehicle.** One specification is compiled to a loss (through a differentiable logic chosen by the user, or a custom one via `DifferentiableTensorLogic`), to verifier queries, and to Agda or Rocq. The Boolean semantics serves verification and the quantitative one serves training, so Bool and cost coexist as two interpretations of the same law. Unlike Luthier, it is about networks only, it doesn't do property-based testing, and the loss value is never recorded. One mechanism is worth taking. Its `.vcl-cache-index` stores "the file path and hash of any external resources … the original specification, the networks and the datasets", and `vehicle validate` rehashes them; "if the new hashes match … the check passes". In Rocq a `vehicle_validate` tactic "trusts the cached solver result if the recorded file hashes still match" (https://vehicle-lang.readthedocs.io/en/latest/exporting.html). That is F3 (certificates keyed by content hash) together with F6 (an extern, here a network file, at a declared type) in a shipped tool.

**PSL / hinge-loss Markov random fields.** Each rule's penalty is its weighted "distance to satisfaction", a hinge loss, and MAP inference minimises "the total weighted distance to satisfaction". Two statements in the paper (https://www.jmlr.org/papers/v18/15-631.html) give the logical limit. The Łukasiewicz operators "correspond to the Boolean logic operators for integer inputs", and hard constraints can be read "as allowing a weight w_j to take an infinite value". Linear or squared hinge is chosen per rule. It differs from Luthier in being a modelling language for joint inference over many uncertain facts, with no functions under test and no record of evidence. Worth taking: Bool law = cost law with infinite weight, and each law's weight and loss shape exposed as parameters (F13: every criterion a parameter).

**Lawvere logics (Bacci, Mardare, Panangaden, Plotkin).** These are the mathematical home of F15. Truth values live in [0,∞] with 0 = true and ∞ = false. In Rational Lawvere Logic "formulas such as ¬φ … evaluate either to 0 ('true') or to ∞ ('false')", and conjunction and disjunction are derived operators. The propositional logics have natural deduction systems that are decidably complete, using Fourier-Motzkin elimination (https://entics.episciences.org/12292). Rational Lawvere Logic (CSL 2026) adds multiplication and division; satisfiability is NP-complete for the affine fragment and in PSPACE in general. I found no implementation. Worth taking: for laws whose cost is linear in other costs, a decision procedure exists, so a "proved" grade is within reach for that fragment instead of only "sampled". The same group's quantitative equational logic (s =_ε t, https://lmcs.episciences.org/14636) is the matching account of F1 (type = theory) when the axioms are distances.

**Cost-guided testing (Hypothesis `target()`, S-TaLiRo/Breach, STL robustness).** These are the only places I found where a real-valued law drives a test generator. In Hypothesis, `target(observation)` gives "feedback with which to guide our search for inputs that will cause an error", does not fail the test by itself, and "test statistics include the best score seen for each label". S-TaLiRo turns falsification into global minimisation of a robustness metric, whose sign is the Boolean verdict. They differ from Luthier in that the cost is a search heuristic, not the law's value, and nothing persists beyond the run. Worth taking: when a law is cost valued, the certificate should store the worst cost seen and the input that reached it, next to the seed and the number of cases. That is what Hypothesis prints and throws away.

## 3. Features with nothing found in this cluster

- **F4** (holes): nothing found.
- **F5** (several implementations compared and the choice recorded): nothing found.
- **F7** (Real vs Float64, laws checked within a tolerance): nothing found.
- **F11** (a minimal kernel with its interpreter stated in the language itself): nothing found.
- **F14** (written for AI authors and human readers): nothing found.
- **F9**: only weighted programming's weighted traces come close.

No candidate combines cost-valued laws with graded, persistent certificates, which is the core of F3 together with F15. Vehicle records Boolean verification results by hash; Caesar finds necessary assumptions but stores nothing; none records the measured cost.

For testing driven by a prior over inputs times a cost of failure, I found no language or PBT tool. Risk-based testing (risk = probability × impact) is process guidance only, as in the survey https://arxiv.org/abs/1801.06812. Conservative Bayesian inference gives the mathematics of a prior on failure probability updated by failure-free tests (Salako and Zhao 2024, https://arxiv.org/abs/2208.07935), but nothing ties it to laws or generators. QuickCheck's `certainty`/`tolerance` is the nearest built-in notion of a declared level. The docs I read don't name the statistical test it uses (UNVERIFIED).

## 4. Surprising

- **Vehicle's Rocq backend** hands back to the proof assistant a solver result trusted by file hash. It is a working instance of "membership is a certificate, nothing is checked twice" across a foreign boundary, and the closest thing to F3+F6 I found in any cluster.
- **Caesar's 2025-26 slicing work** (Brutus, ESOP 2026 per the Caesar site) uses the word "certificates" for slices that still verify. I read only the abstract, so whether they are persisted is UNVERIFIED.
- **Simulation distances** (Černý, Henzinger, Radhakrishna; https://research-explorer.ista.ac.at/record/3249) replace the Boolean result of refinement checking with a distance, true = 0. It is a precedent for "a law that compares implementation and specification returns a discrepancy".
- **Weighted programming** (OOPSLA 2022) is the nearest thing to a general-purpose language where the semiring of weights is a parameter. The paper models the ski-rental optimisation problem; that it uses the tropical (min-plus) semiring for it is UNVERIFIED (abstract read only).
- **Vehicle and LDL make the choice of differentiable logic a parameter.** LDL shows that Gödel and most fuzzy differentiable logics are sound but incomplete relative to intuitionistic first-order logic. So the Bool limit of a cost logic is not automatic once quantifiers enter, which matters if Luthier wants Bool laws to be exactly the 0/∞ special case.
