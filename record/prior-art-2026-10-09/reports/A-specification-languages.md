### 2. The closest candidates

**ACL2 / ACL2s.** This is the closest in spirit. The logic is the executable language. `defdata` keeps two readings of every type: a predicate, and an enumerator derived from the definition. Range types such as `(range rational (0 < _ < 1))` are native, and cgen samples from the enumerators to test conjectures, with a seed threaded through. A function introduced in `encapsulate` without a body is a hole with constraints. `defattach` attaches an executable function without changing the logic, which is very close to F4. `mbe` holds two implementations, proven equal, of which only one runs. Certified books record checksums of what they include, and `defaxiom`/`skip-proofs` require explicit flags. How it differs: untyped, no evidence grades, and certificates are files per book rather than per definition. Mechanism worth taking, for F7: `binary-df+` is defined logically as `(df-round (+ x y))`, where `df-round` is a constrained function. It is only required to return a rational, and the rounding mode is left open. The Float operation is the ideal operation followed by a rounding that is itself a hole. That is a precise way to state "Float64 refines Real" ([Kaufmann & Moore](https://cs.utexas.edu/~moore/publications/double-float.pdf), section on df operations).

**PVS.** Predicate subtypes are F1's `{ f | laws }` almost literally. Every coercion into a subtype generates a TCC, which is an obligation at the boundary (F6), discharged statically. The status bookkeeping is the closest thing to F3's weakest link: "Proof of TCCs can be postponed, but the system keeps track of all undischarged proof obligations and the affected theories and theorems are marked as incomplete" (TSE 1998, p. 2). Random testing generates values from types, and subtypes are handled by rejection. How it differs: the status is binary (complete or incomplete), there is no grade for sampled evidence, and tests leave no record. Mechanism worth taking: `random-test :instance "Th[int]"` supplies ground values for a theory's parameters and uninterpreted constants, so you can test against a hole by giving a temporary model, and the instance is named in the command ([Owre](https://pvs.csl.sri.com/doc/5-Owre.pdf)).

**VDM with QuickCheck (2024).** It runs each proof obligation through pluggable value-generation strategies that respect type invariants. It returns FAILED with a counterexample, MAYBE, or PROVABLE. The "finite" strategy generates every value of a small type, so a pass there counts as exhaustive. A random seed can be fixed for repeatable runs. These are close to F3's grades (point, sampled, exhaustive). How it differs: the verdicts are reports, not persistent certificates, and there is no chain. Mechanism worth taking: a strategy interface that receives the obligation and its type bindings and returns values, or directly a verdict with a witness. That makes the grade a property of the strategy that produced the evidence ([arXiv 2410.02046](https://arxiv.org/abs/2410.02046), section 2).

**Why3.** Theories with abstract symbols are filled by `clone` or by realizations in Coq/Isabelle (F4). `ieee_float` states each float operation as round(real operation), which is F7 in the same form as ACL2. Sessions persist proof attempts and mark the ones whose goal changed as obsolete. How it differs: there is no testing, and the manual itself warns that "Why3 does not track dependencies between realizations and theories, so a realization will become outdated if the corresponding theory is modified" (itp.rst). Content-hash certificates (F3) would close exactly that gap. Mechanism worth taking: re-associating old evidence with changed goals and flagging it obsolete, instead of discarding it.

**Lean 4.** Structures and classes are theories with laws, and `#print axioms` gives every theorem's chain of assumptions (F3's "every chain ends in assumptions"). Mechanism worth taking, for F5: two grades of "this implementation is the concept". `@[csimp]` swaps in an implementation only with a proof of equality. `@[implemented_by]` swaps it in unchecked, and the docs warn this can prove False through `native_decide`. On top of that, `native_decide` creates "a bespoke axiom for each invocation… so each axiom can be audited for the precise statement that it proves". That is a per-computation assumption record ([Axioms](https://lean-lang.org/doc/reference/latest/Axioms/), [implemented_by](https://lean-lang.org/doc/api/Lean/Compiler/ImplementedByAttr.html)).

### 3. Features with nothing found in this cluster

- F3 in full: no system keys certificates by content hash or grades evidence beyond proved/unproved. PVS and VDM come closest.
- F5's measured costs, with the fastest implementation chosen per case and the choice recorded: nothing.
- F8's statistical laws with level and power, and Bayesian reading of evidence with the prior as a parameter: nothing.
- F9's trace (a partial order of actions with results and costs) and the world reached through hash-pinned files: nothing.
- F10 provenance: only seeds (Quint, VDM QuickCheck, ACL2s).
- F13 (every criterion a parameter): nothing beyond ordinary theory parameters.
- F15: only the theory (quantitative algebra); no language implements quantitative laws.
- F14 and F16: only Imandra/CodeLogician and Pathway Logic, both partial.
- Not reached (search budget): F*, Event-B/Rodin, Alloy, Z, TLA+/Apalache, OBJ/CafeOBJ, Agda, Twelf. From memory, all UNVERIFIED: Alloy's bounded scope matches the "bounded" grade, and F*'s `assume val` and its erased reals touch F4 and F7.

### 4. Surprises

- **Pathway Logic** (SRI; Talcott, Eker, Lincoln and others) models signal transduction networks as Maude rewrite theories, with reactions as rules, and uses search and model checking over them. It is biology on a specification language, though with no Python or statistics ([PSB 2005](https://www.csl.sri.com/papers/1552/psb-05.pdf), [overview](https://pl.csl.sri.com/Presentations/about-pl.pdf)).
- **Clojure spec** (outside the cluster). Generators come from specs automatically. `s/fdef` with `:args/:ret/:fn` makes a function's spec its test, run with `stest/check`. `stest/instrument` checks arguments at run time. That covers parts of F2, F6 and F8 ([guide](https://clojure.org/guides/spec)).
- **Unison** (outside the cluster). Definitions are identified by a hash of their syntax tree, and deterministic tests are not rerun when their dependencies are unchanged. This is the content-hash half of F3 and F10, without grades ([the big idea](https://www.unison-lang.org/docs/the-big-idea/)).
