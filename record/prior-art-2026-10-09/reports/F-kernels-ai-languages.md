## 2. Closest candidates

**Aver.** The nearest overall, and its stated audience is Luthier's: AI writes the code, a human inspects and constrains it. A law looks like `verify add law commutative / given a: Int = -2..2 / given b: Int = [-1,0,1] / add(a,b) => add(b,a)`. Laws sit next to the function and expand the Cartesian product of the declared domains, which is deterministic and capped at 10,000 cases. Selected laws are exported to Lean as theorems. `decision` blocks (date, reason, chosen, rejected, impacts) are language syntax, close to Luthier's decision log. Effects can be recorded and replayed. Where it differs: laws are examples over hand-listed finite domains, with no random generators derived from types, no statistics and no Bayesian reading. There is no laws-as-types: a type is not a theory. The certificate is all-or-nothing on a wasm artifact (CERTIFIED or decline), so it has no evidence grades and no chain graded by its weakest link. Nothing on Real vs Float or foreign implementations. **Worth taking:** the ABC's explicit list of the trusted base plus the fail-closed verdict naming the failing gate. That is a concrete form for Luthier's rule that every chain ends in assumptions (https://averlang.dev/certificate.html).

**Unison.** The only language where "nothing is checked twice" is built in. Definitions are hashes of their syntax trees, typechecking is cached forever, and test results are cached until some dependency's hash changes. `structural` vs `unique` types is exactly Luthier's structural vs nominal distinction, implemented by hashing (a unique type gets a UUID mixed into its hash). Differences: no laws attached to types, no grades (a test passed or it didn't), and property testing is a library function. **Worth taking:** identity of a type or term is the hash with names removed, and nominality is a salt in the hash. That gives F3's content-hash keying and F12's structural/nominal split one mechanism (https://unison-lang.org/docs/language-reference/unique-types).

**Urbit jets (and Simplicity).** Both have a tiny reference kernel and native implementations that replace kernel expressions. Urbit registers each C jet against the Hoon/Nock code it replaces, with a flag meaning "is this jet already known to be correct?". When the flag says no, the runtime checks the C result against the Nock reference. Simplicity identifies jetted expressions by Merkle root and has its semantics in Coq. Difference from F5: there is one reference and one native version, with no cost measurement and no choice per case recorded. **Worth taking:** the per-implementation flag "verify against reference at run time" vs "trusted". It is a minimal version of Luthier's equivalence certificate and could become a grade (https://docs.urbit.org/build-on-urbit/runtime/jetting).

**Shen and shen-backpressure.** Shen types are sequent rules whose side conditions are executable predicates, so a type is a subset cut out by checks, near F1. The 2026 project shen-backpressure has a human edit `specs/core.shen` while agents write Go/Python/TS code that can only build domain values through generated, checked constructors. That is F6 plus F14 with a Python target. Differences: there are no laws over functions (only invariants on data), no testing of laws, and no evidence records. **Worth taking:** compile the reviewed spec's invariants into opaque guard constructors in the foreign language. That is a concrete route for F6 on the Python side (https://github.com/pyrex41/shen-backpressure).

**Lean4Lean / MetaCoq.** These are the state of the art for F11: a kernel written in the language, related to a formal statement of its type theory. MetaCoq names the shift Luthier wants, from a trusted code base to a trusted *theory* base. Both are large; neither fits "executable by hand on paper". **Worth taking:** the TCB-to-TTB framing as the stated goal for certifying the host (https://popl20.sigplan.org/details/POPL-2020-Research-Papers/36/Coq-Coq-Correct-Verification-of-Type-Checking-and-Erasure-for-Coq-in-Coq).

**Quint.** An executable spec in readable syntax, positioned in Nov 2025 as the artifact humans validate while LLMs write code. Two levels of evidence are distinct tools: random simulation (`quint run`) and model checking (`quint verify`). Model-based testing replays spec traces against the implementation. It is a spec language for state machines, not a typed language with laws-as-types. **Worth taking:** model-based testing, which drives the implementation with traces generated from the plan and compares. It fits F9's plan vs execution (https://quint.sh/posts/llm_era).

## 3. Features with nothing found in this cluster

- F3 as a whole: graded, persistent certificates (point, sampled, bounded, exhaustive, witnessed, proved, assumed) recording seed and generators, chained by weakest link. Only fragments exist: ACL2's "less trustworthy" annotation, Vera's proved vs runtime-checked, Vow's "bounded", Unison's hash cache, Aver's binary certificate.
- F5's measured costs and recorded choice of implementation per case.
- F8's statistical laws with level and power, and the Bayesian reading with the prior as a parameter.
- F13 as a principle. Only Aver exposes case budgets as configuration.
- F15 (laws valued in a discrepancy or cost, Lawvere-style): nothing in this cluster.
- F16 together with F14: no AI-oriented spec language aimed at biology or scientific analysis. LeanLJ is the only science case, and it targets proof, not AI authorship.

## 4. Surprising

- **There are now dozens of "languages for AI authors"**: a catalogue lists 42, split into syntactic, verification and orchestration camps (https://agentlanguages.dev/). Most are 2025-26 hobby or one-author projects with agent files (CLAUDE.md, AGENTS.md) shipped in the repo. Aver and Vera are the serious ones. None has laws as types or graded evidence.
- **ACL2 certificates** are the oldest close match to F3's chain (decades old). The `.cert` file records checksums of every book involved, and the trust tags and skipped proofs it inherits from included books. That is a working, industrial "chain of certificates ending in assumptions", though it has only two levels (trusted or not).
- **LeanLJ** (Molecular Physics 2025) does F7 in practice: one polymorphic definition, theorems over ℝ, computation over Float. It gives no tolerance guarantee on the Float side, which is the gap Luthier's "checked on doubles within a tolerance" would fill.
