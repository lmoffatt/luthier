(2) SCHEMA (src/distance_graph.py:3-14; luthier/distance_graph.lut:3-7). Typed CSV of luthier.tables (v0.1-final:src/luthier/tables.py docstring): header cells name:type, type in {int,float,str}; reader tolerates CRLF, spaces, extra digits; rejects unknown type, repeated column, wrong cell count, unparsable number, non-finite float.
- nodes.csv: name:str, x:float, y:float, z:float, sx:float, sy:float, sz:float. Row n = node n. x,y,z prior mean in metres (z = height from the ground, enters the prior only); sx,sy,sz prior sd in metres.
- measurements.csv: i:int, j:int, d:float. i,j = 0-based row indices into nodes.csv; d = horizontal tape distance in metres, on the floor. Repeated pairs allowed.
- Missing value: there is none. An empty numeric cell is "a number that does not parse": read_graph raises ValueError("<path>: <parse error>") (src/distance_graph.py:33-43) before any invariant runs. Extra columns are not rejected by the invariants (they only test that the required ones exist).
Invariants, in the order checked (distance_graph.lut:73-76 and firstViolation :103-106; fast twin src/distance_graph.py:157-199). Row numbers are 0-based (firstFailing from 0, :67-70). Output format from validate_graph.lut:26-30: schema -> "FAIL <Name>"; row-wise -> "FAIL <Name>: <table> row <k> (<col>=<val>, ...)" via row_text (distance_graph.py:202).
- HasNodeColumns (:26-28): the 7 node columns with their types. Prints "FAIL HasNodeColumns".
- HasMeasurementColumns (:30-31): i:int, j:int, d:float. "FAIL HasMeasurementColumns".
- IndicesInRange (:50): 0 <= i,j < number of nodes. "FAIL IndicesInRange: measurements row k (...)".
- NoSelfPairs (:51): i /= j. measurements row.
- DistancesPositive (:52): d > 0. measurements row.
- PriorSdPositive (:56): sx, sy, sz > 0. "... nodes row k (...)".
- NamesUnique (:57): no earlier node has the same name. nodes row.
- PriorSeparated (:54-55): the prior means of i and j differ ON THE FLOOR (horizontal pairDistance > 0), because the Jacobian divides by it. measurements row.
Valid -> "valid: N nodes, K measurements, P distinct pairs; directions the distances do not see: U (of which N are the heights and 3 the rigid motions of the plane)" (validate_graph.lut:32-36). If the fast check passes a graph the native ValidGraph rejects: "the check reported nothing on a graph that is not valid" (:42).
Not checked: the triangle inequality on triangles with three measured sides. The A2 block passes validate_graph and only shows up in the fit (sigma 25.7 cm vs 4.9 without it, on the old 3D model). Luciano's note asks for it in ValidDistanceGraph: Lucianos feedbacks/oct 6 0734.txt:16-17.

(3) CONSTRUCTS AND LIBRARY (v0.1-final line numbers are in src/luthier/lib/ and src/luthier/core.lut at that tag).

- Definitions `f (x : A) (y z : B) : C := e`.
- Record types `R = { a : A, ... }` (distance_graph.lut:19, :84, :121); record literals `{ a := e, ... }` (:88, :124-129); field access chains (g.measurements.nRows, r.invariant, m.x0.n).
- Sum type `< schema : String | inRow : RowViolation >` (:85); injection by constructor application (`schema "HasNodeColumns"`, `inRow {...}`, `just v`, `nothing`).
- `match e { ctor x -> ... ; ctor y -> ... }` on sums and Maybe. `match e { x -> body }` used as let (no `let` keyword anywhere in these files; validate_graph.lut:40-41, distance_graph.lut:88, :142-144).
- `if/then/else`, including nested else-if.
- Refinement types `T : U := { g : A | P g }` (:34, :78; distance_graph_python.lut:41-42, :55); refinement with conjoined lambda predicates `{ f : A -> B | \ (g : T1) { P f g } & \ (g : T2) { Q f g } }` (python.lut:84-87) and `{ v : A | P v & Q v }` (:79, :93).
- Implicit subsumption: ValidDistanceGraph and GraphWithColumns values passed where DistanceGraph or GraphWithColumns is expected. Flow refinement: in validate_graph.lut:42, `if ValidGraph g then summary g`, the branch needs g : ValidDistanceGraph (the v0.1 R11 rule, refined type inside `if p x`).

- Lambdas `\ k { e }`, `\ a n { e }`, typed `\ (g : T) { e }`.
- Vector literal `(n, \ k { e })` and matrix literal `(r, c, \ a b { e })` (:125-129; python.lut:38).
- `extern "python:module.fn"` for values (validate_graph.lut:23-24; python.lut:48, :54, :57, :88) and `gen T := extern "..."` (python.lut:43-46, :56).
- `test name with N` (python.lut:95-100).
- Operators: String `+`; Int `*`, `/`, `mod`, `-`; comparisons `== /= < <= >= >`; `and or not`; Mat*Mat through `operator * := matMul` (array.lut:364).
