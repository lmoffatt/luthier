## What was counted and how

A clause is an item of `docs/spec/*.md` whose heading (`**N.Sk.**` or `**N.Rk.**`) carries as its first status `[decided ...]` or `[proposed]`. There are 131 (122 decided, 9 proposed; the script that extracted them tags each item by the first bracket after its heading). `grep -c -E "\[(decided|proposed)" docs/spec/*.md` gives 196 because it counts lines: items already `[implemented]` that carry `[decided ...]` sub-paragraphs, the status legend of 00-index.md and inline mentions. The brief estimated 123; the item count is 131.

Classes. implemented: the running tool (Python, or a theory with its model for what is a theory) does what the whole clause says, with a file and line or a test. postponed: a decision (record/decisions.md), a plan entry or a comment in a theory (`lib/*.lth`) leaves it out; where a part is done, the evidence names it. pending: decided or proposed, nothing implements it and no decision or theory comment postpones it. A clause with any operative part missing is not "implemented". Pending clauses whose only mention of the omission is a comment in a `.py` file (not a theory, not a decision) are marked "comment only": they are the postponements written in code and nowhere else, the failure the plan names.

Verification was by grep and reading the cited regions, not by running the suite. Where the spec text says "[implemented] Today ..." inside a decided item, the evidence below was re-checked against the code, not taken from the spec. Several spec statements are stale (5.S3, 5.S9, 5.S10 say a library "is not written"; it is).
